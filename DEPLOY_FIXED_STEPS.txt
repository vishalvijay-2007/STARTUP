STARTUP DEPLOY FIX

The GitHub Pages frontend must call the Render backend, not /api on GitHub Pages.

Fixed in this package:
1. client/src/App.jsx now uses https://startup-api-3shs.onrender.com/api in production when VITE_API_URL is not supplied.
2. .github/workflows/deploy-frontend.yml now explicitly sets VITE_API_URL to the Render API during the GitHub Pages build.
3. Local development still uses http://localhost:5000/api.

IMPORTANT AFTER COPYING THIS PROJECT:
Your current Git branch is feature/final-project-submission. The Pages workflow runs only when main is updated.

PowerShell:
cd E:\StartUp_Fixed\StartUp
npm install
npm --prefix client install
npm --prefix client run build
git add .
git commit -m "Fix GitHub Pages API connection"
git push origin feature/final-project-submission

Then open the Pull Request from feature/final-project-submission into main and MERGE it.
After merge, GitHub Actions -> Deploy frontend should run automatically.

Backend check:
Open https://startup-api-3shs.onrender.com/api/health
It should return JSON such as {"ok":true,...}.

Do not set VITE_API_URL to /api for GitHub Pages. GitHub Pages does not run the Express API.
